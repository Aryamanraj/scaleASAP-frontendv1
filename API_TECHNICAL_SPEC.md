# ScaleASAP: Technical API Specification & Functional Roadmap

This document serves as the master technical reference for the development of the ScaleASAP backend. It maps out the requirements for every API endpoint, data model, and AI generation trigger identified in the high-fidelity frontend.

---

## 1. Core Data Models

### Workspace
| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary Key |
| `name` | String | User-defined workspace name |
| `owner_id` | UUID | Link to Auth user |
| `data_sources` | JSONB | Map of connected platforms (LinkedIn, Gmail, etc.) |

### Campaign (Strategy)
| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary Key |
| `name` | String | e.g., "Amazon DSP Fleet Optimization" |
| `status` | Enum | `active`, `paused`, `completed` |
| `strategy_payload` | JSONB | AI-generated strategy criteria (output from Discovery) |
| `discovery_rate` | Integer | Leads to find per day |

### Lead
| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary Key |
| `campaign_id` | UUID | Foreign Key |
| `status` | Enum | `found`, `enriched`, `drafted`, `sent`, `responded` |
| `outcome` | Enum | `meeting_booked`, `interested`, `rejected`, `no_response` |
| `enrichment_data` | JSONB | Signals, Experience, AI Summary |

## 2. API Endpoints & Logic

### Discovery & Strategy (The "Brain")
These endpoints handle the initial extraction of user intent and the generation of a scalable strategy.

#### `POST /api/discovery/analyze`
*   **Source**: Onboarding / Home (Discovery Chat)
*   **What it does**: Takes the raw user input ("I help Amazon DSPs optimize fleet costs") and processes it through an LLM.
*   **Result**: Returns a structured **WorldView** (Ideal Customer Profile, Pain Points, Buying Signals).
*   **Edge Case**: Input is too vague.
    *   *Logic*: The API should return a "Clarification Required" status with suggested questions.

#### `POST /api/campaigns/create`
*   **Source**: Discovery Finish CTA
*   **What it does**: Persists the WorldView into a formal Campaign.
*   **Result**: Initializes the background discovery engine for that specific strategy.

---

### Lead Management (The "Engine")
Handles the ingestion, enrichment, and tracking of prospects.

#### `GET /api/leads`
*   **Source**: Campaign Detail Curtain (Leads Tab)
*   **Logic**: Must support complex sorting:
    *   **Relevancy**: A score (0-100) generated by AI comparing Lead Bio vs. Campaign Strategy.
    *   **Activity**: Timestamp of the last status change.
*   **Edge Case**: 0 leads found.
    *   *Logic*: Return 200 with empty array, but provide "Engine Health" metadata (e.g., "Searching...").

#### `POST /api/leads/scale`
*   **Source**: "Scale Campaign" CTA
*   **What it does**: Forces an immediate run of the discovery engine.
*   **Logic**: 
    1.  Trigger Scraper/Search for 2-5 new profiles.
    2.  Stream "Found" status updates (simulated via WebSockets or Long Polling for the frontend skeletons).
    3.  Enrich profiles and return them.

#### `POST /api/leads/log-outcome`
*   **Source**: Lead Profile Detail Actions
*   **What it does**: Updates `outcome` and `outcome_reason`.
*   **Logic**: This data MUST be fed back into the Discovery Engine's embedding space to refine future lead searches for that campaign.

---

### Content Generation (The "Voice")
Where AI generates the actual outreach value-add.

#### `POST /api/leads/generate-outreach`
*   **Source**: Lead Detail -> Outreach Tab -> "Generate" CTA
*   **Input**: `lead_id`, `format` (LinkedIn/Email), `is_followup` (bool).
*   **Logic**: 
    *   Combines **Lead Signals** (e.g., "Alexander expanded his fleet") with the **Campaign Hook**.
    *   Must produce a "Human-in-the-loop" editable draft.
*   **Edge Case**: Lead has no recent signals.
    *   *Logic*: Falling back to a "Foundational" message based on Job Title and Company trajectory.

## 3. High-Fidelity UX Logic (Frontend Interaction)

### Hold to Delete Guard
*   **Logic**: Handled on the client (`onPointerDown`), but the API (`DELETE /api/campaigns/:id`) should perform a "Soft Delete" first (move to `deleted_at`) before permanent wiping after 30 days.

### Sorting & Filtering
*   **Functional Requirement**: Sorting logic shouldn't just be alphabetical. Developers need to implement a **Relevancy Vector** in the database (e.g., using pgvector) to allow the "Relevance" sort to be truly functional based on the strategy.

---

## 4. Summary of AI Generation Points

1.  **Discovery Analysis**: Input URL/Bio -> Output ICP/Pain Points.
2.  **Lead Enrichment**: Lead Name/URL -> Output Research Signals & Citations.
3.  **Strategic Why**: Campaign + Lead -> Output "Why this lead matches now."
4.  **Outreach Personalization**: Lead Bio + Signals -> Output Personalized Message.

> [!IMPORTANT]
> All AI-generated content should include **Citations** (Source Name, URL, Logo) wherever possible to build trust with the user.
